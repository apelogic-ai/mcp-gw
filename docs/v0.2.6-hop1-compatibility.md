# v0.2.6 HOP-1 Resource-Server Compatibility

MCP-GW `v0.2.6` is an OAuth resource server. It accepts deployment-provided issuer profiles and
does not issue HOP-1 tokens, operate user login, or own an authorization server. Provider consent
and provider credentials remain separate from front-door authentication.

## Compatible Behavior

For a valid, unambiguous issuer profile, `v0.2.6`:

- advertises discoverable authorization servers through MCP protected-resource metadata;
- verifies the exact issuer and one configured MCP audience;
- restricts JWT verification to a deployment-provided algorithm allowlist;
- verifies the JWT signature against the configured JWKS endpoint;
- rejects expired tokens and tokens used before their `nbf` time;
- requires a stable, non-empty subject claim and configured email claim;
- does not forward the HOP-1 bearer token to Google Workspace, GitHub, or another MCP backend;
- keeps provider OAuth tokens inside the corresponding wrapper-to-provider path; and
- keeps the gateway ready when an issuer JWKS endpoint is unavailable while requests that depend
  on that issuer fail closed.

The public chart enables no workload, issuer, backend, hostname, registry, or Secret by default.

## Known Contract Gap

`v0.2.6` validates the fields in each issuer profile but does not reject every ambiguous profile
set at process startup. In particular, duplicate profile names, duplicate issuer URLs, duplicate
audiences, and empty audience arrays can pass the wrapper JSON parser. The gateway authentication
layer still validates each request, but this startup behavior does not meet the stricter
fail-fast configuration contract.

The next patch release closes that gap and expands the local authorization-server fixture to test
discovery, JWKS retrieval, audience-bound token acquisition, successful MCP initialization, and
rejection of wrong issuer, audience, algorithm, signature, expiration, and not-before claims.

## Upgrade Guidance

Deployments using one valid issuer profile can upgrade without changing values. Deployments with
multiple profiles must ensure that profile names and issuer URLs are unique, and that audiences
and algorithms are non-empty lists without duplicate entries.
